# 0054 — First executable coastline comparison, not shipping acceptance

Date: 2026-10-20
Status: approach and implementation authorized; host comparison implemented and user visually accepted; no-omission proof, target performance and physical-display acceptance open

## Decision

Treat coastlines as orientation graphics on a small 1-bit display, **not** pixel-perfect reference geography. The user validated the **40 km simplified appearance** for this comparison and authorized proceeding with one bounded executable slice. This does not reopen [0053](0053-no-resolvable-coastline-omissions.md): a resolvable, screen-relevant coastline may not routinely gain gaps or disappear due to a numeric/work threshold. At 0.1°–<5°, [0051](0051-angular-coastline-appearance-direction.md) remains an evidence-gated investigation, not a new accuracy promise.

For genuinely invalid coastline data or an irrecoverable coastline-only calculation failure, **clear any coast ink and show a separate `COAST ERROR` notice**, preserving Earth, satellites, selection, glyphs and existing notices. A draw-target/physical write error fails the whole frame, not just the coast. The user separately approved this exceptional treatment. A difficult but resolvable view is not an exceptional failure policy.

## Bounded first host comparison

The pinned [Natural Earth candidate](0052-natural-earth-coastline-candidate.md) is exported by the checked [generator and provenance](../../render/assets/README.md) using 40 km ECEF reduction and a trial 1e-4° integer encoding. The renderer reads the static 15,484-byte part/vertex asset without heap allocation, scans all 1,734 retained segments with finite ≤0.2° interpolation and 24-step tangent bisection, clips camera-facing surface strokes to the wide rectangle, then draws coast before limb, aim point, arrows, markers, strip and white-backed notices. It checks asset boundaries and coordinates before drawing. A coastline-only failure clears the frame and repaints without coast, with `COAST ERROR`; display errors propagate as frame errors. Square/circular radar output does not use the asset. No runtime fetching, new dependency or firmware work.

The checked decoded export has **23,377 interpolated intervals** (maximum 108 steps per stored segment); the runtime checks these limits before writing pixels. The user reviewed [seven retained executable scenes](../mockups/0061-first-executable-coastline-review.md) and tried the simulator, confirming that the 40 km coastline appearance looks good in both. This accepts the visual comparison, not the renderer's numerical completeness or device performance. The per-segment bounds and finite dataset ensure the comparison terminates; they are **not** a certified visibility/error bound or an S3 time limit. In particular endpoint/midpoint visibility plus fixed sampling can miss a narrower visible excursion; integer-line raster differs from the offline continuous-stroke diagnostic. Neither small quantization nor 40 km reduction proves all tight-zoom coast pixels. This is a concrete comparison to review and improve, **not proof that 0053's no-omission condition has been met on every supported scene**. Do not treat a sample that hides visible geography as approved normal behavior.

## Remaining gates

The retained executable scenes and interactive simulator appearance have been visually accepted. A subsequent host verification suite adds in-process coast/no-coast selected and empty/notice frame controls, eight-times-denser point probes on the checked export across SF 0.1°/1°/5°/100°, polar 20° and dateline 5°, and synthetic front/hidden limb, viewport corner and separate-run checks (`render/src/coast.rs` and `render/src/lib.rs` tests). These controls passed without an observed gap. They allow a three-pixel raster/chord difference, skip uncertain facing/viewport edges and sample only finite points on the *same simplified asset*: nearby strokes can also mask a missing run. They cannot exclude narrower missed excursions between probes, prove source-geography completeness or certify the tangent on all observers. The synthetic split is not a second checked asset. A second host slice tests **individual exported segments** against eight-times-denser points so other coast strokes cannot mask a missing run. It tests the six named scenes plus reproducible observer positions computed near the camera limb (20°/100°) and horizontal viewport edge (0.1°) for a stratified set of sufficiently long segments. No qualifying omission was found; the checks require three distinct interior sample pixels and allow a three-pixel neighborhood, so they do not certify shorter runs, excursions between points, near-edge samples, other observers or a mathematically bounded error. They neither change the renderer nor establish that the whole-layer control proves completeness. Further adversarial crossing and independently bounded sampling/visibility work remain needed before declaring no ordinary omission. A [selected-segment host study](../evaluations/m4-coastline-bounded-segment-study.md) conservatively encloses position, facing and viewport/screen cells instead of trusting the runtime's fixed point probes; it finds no qualifying missing cell for three segment-46 observers or four short (2–7 reference cells) exported viewport-edge runs with a one-pixel allowance. It keeps uncertain subintervals unknown, including 1–2% of the short-run segment parameters. A separate seven-scene test checks all 1,734 exported segments in isolation, confirming their bounded *possible* screen cells have nearby ink within 3px; it does not infer invisibility from unknown. This is finite-scene, simplified-asset evidence, not a directed-rounding proof, independent source geography or an all-observer result; 0053 remains open. A host regression now forces a coastline-only failure after a real stroke has emitted ink and compares selected/empty, warning/no-warning frames with no-coast controls plus `COAST ERROR`; the pixel-level rollback passed. The test hook is not a naturally occurring numeric failure, a cost sample or proof of no omissions. Visual acceptance alone cannot prove completeness. A [host-only cost preflight](../evaluations/m4-coastline-host-cost-preflight.md) records release-test rebuild/full-frame timings and raster writes across reviewed and boundary scenes; these are not S3 time or compiled-size evidence. Compare observed compiled addition, S3 full coast rebuild and scratch against [provisional gates](../evaluations/m4-coastline-budget-preflight.md) only after **separate firmware/hardware authorization**. Sharp/display throughput, whole-device frame time/stack and physical-display acceptance remain open; frozen M2 evidence is unchanged. If this simple candidate cannot pass those gates, revise or reject it—not downgrade 0053 silently.
