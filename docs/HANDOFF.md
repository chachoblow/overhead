## Risks and open concerns
- OTA TLS capped at 1.2 (like CelesTrak): if GitHub or CelesTrak drop 1.2, devices fail closed until an update. A host CA change while a device is offline longer than a release cycle strands it until USB.
- `failed_build` remembers only the last failure. A power cut between saving `pending_build` and writing `otadata` would mark that build failed (harmless: the next build installs).
- The 2026-11-06 device-app `NO FRAME` (cause unknown; KoD/NIST candidates fixed by 0080–0082) has not recurred (none in the 72 h soak); a recurrence blocks gift readiness. The app now resets on panic.
- Inputs (IO7 selection, IO6 knob switch, [0088](decisions/0088-selection-button-and-captured-knob-switch.md)): ~34–41 ms sampling gap during Wi-Fi association (a press under ~60 ms can be missed then); polarity/20 ms debounce provisional ([0068](decisions/0068-boot-selection-gesture.md), [0070](decisions/0070-boot-input-capture-independent-of-render.md)). Fetch TLS stalls the display ~450–485 ms (VCOM 500 ms); CPU0 stack ~21 KiB; selection ~165 ms and knob ~86 ms frame hitches accepted ([0060 note](decisions/0060-defer-timing-to-physical-prototype.md#note--2026-11-05-24-hour-soak-limits-accepted)).
- iOS app: reconnect after a link loss during `Testing` is untested on hardware; App Store review not yet tried.
- Setup: a factory reset returns the channel to `stable` and BLE can't set it (fine for gifts, and `stable` now has a manifest; the user's board would need a `beta`-seeded USB flash after a reset). No board has run `stable` yet. Not shown: a slow router recovering inside the 10 min setup window, setup on another iPhone (gift readiness).
- Host-tested only: post-GET fetch failures, a >100 ms SNTP jump, near-budget NIST replies, settings/otadata cut-write points.
